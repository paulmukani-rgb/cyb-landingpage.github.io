Answers

Frequently asked questions

Everything enterprise buyers usually ask before a technical evaluation.

Where is customer data physically hosted and processed?

All primary production environment infrastructure, customer databases, and backup arrays are securely hosted within highly resilient, multi-region cloud deployment zones. By default, customer production data is stored within geographically segregated regions (e.g., AWS eu-west-1 / af-south-1) to ensure compliance with strict regional data residency borders, international privacy regulations (such as GDPR, CCPA, and regional Data Protection Acts), and sovereignty mandates. No data is transferred across international jurisdictions without explicit customer authorization.

How is data protected both at rest and in transit?

We enforce strict cryptographic controls across all data states:

  • Data at Rest: All persistent storage volumes, user databases, object storage buckets, and automated system backups are encrypted using AES-256 bit encryption with customer-isolated cryptographic keys managed through automated Cloud Key Management Services (KMS) featuring automated annual key rotation.
  • Data in Transit: All network traffic entering or leaving the platform boundaries is strictly encrypted using TLS 1.2 or TLS 1.3 protocols. Legacy, insecure cryptographic protocols (such as SSLv3, TLS 1.0, and TLS 1.1) are explicitly disabled across all public and private network endpoints.
Does the platform support corporate Single Sign-On (SSO) and Multi-Factor Authentication (MFA)?

Yes. Following the core principles of Zero Trust Architecture (ZTA), the platform fully supports enterprise identity federation via industry-standard protocols including SAML 2.0 and OpenID Connect (OIDC). Customers can seamlessly integrate their centralized identity providers (IdPs) such as Okta, Microsoft Entra ID, Ping Identity, or Google Workspace. Multi-Factor Authentication (MFA) using time-based one-time passwords (TOTP) or hardware keys (FIDO2/WebAuthn) can be strictly enforced globally at the organization level.

How does Vanguard enforce the Principle of Least Privilege (PoLP) internally?

Vanguard operates on a strict "Never Trust, Always Verify" operational baseline. Internal staff members do not possess persistent administrative access to customer production environments.

  • Access is tightly regulated via a centralized Privileged Access Management (PAM) gateway utilizing Role-Based Access Control (RBAC).
  • Engineering and support personnel must request time-bound, context-specific, Just-In-Time (JIT) credentials to perform necessary maintenance actions. Every internal access request requires documented peer review, manager approval, and an active business justification ticket.
How are unauthorized or unverified devices blocked from accessing the environment?

The platform features Continuous Device Posture Attestation. Before an administrative session or connection is authorized, endpoint agents and security controllers validate the device's real-time security posture. If a machine lacks active operating system security patches, has disabled endpoint detection (EDR/Antivirus) software, or attempts access from an anomalous or untrusted geographic location, the access token is automatically blocked or revoked instantly, forcing a step-up authentication challenge.

What is the "blast radius" of the architecture if a single system component is breached?

Vanguard utilizes advanced Network Micro-Segmentation and software-defined perimeters (SDP) to decouple system workloads.

  • The platform architecture isolates web-facing application servers, internal microservices, and primary customer data stores into highly segregated, firewalled VPC subnets.
  • There is no flat internal network. If a single web-facing container or application endpoint is compromised, the attacker is completely restricted from moving laterally because micro-segmentation blocks cross-zone communication by default.
How often does the platform undergo external vulnerability testing?

The application codebase and underlying infrastructure environments undergo an independent, comprehensive Vulnerability Assessment and Penetration Testing (VAPT) exercise at least once per calendar year. These audits are conducted by accredited, certified third-party ethical hacking firms. The resulting executive summaries and clean remediation reports are maintained on file and can be securely shared with prospective enterprise buyers under a standard Non-Disclosure Agreement (NDA).

Do all critical third-party sub-processors maintain independent security validations?

Yes. As part of our comprehensive Vendor Risk Management program, Vanguard continuously audits the security certifications of all critical upstream sub-processors, cloud hosting providers, and software utility integrations. It is a mandatory procurement threshold that all tier-1 infrastructure partners maintain current, active SOC 2 Type 2 reports and/or ISO/IEC 27001:2022 certifications on file. These reports are re-verified annually by our compliance team to prevent upstream supply-chain risks.

What are the platform's target RTO and RPO metrics during an outage?

To guarantee business continuity and rapid disaster recovery, the platform architecture enforces strict operational thresholds:

  • Recovery Time Objective (RTO): < 4 Hours — maximum targeted duration to fully restore system availability following a catastrophic regional cloud failure.
  • Recovery Point Objective (RPO): < 1 Hour — maximum targeted window of potential data loss, achieved through continuous, encrypted differential database backups replicated across multiple availability zones.
What is the notification timeline SLA if a security incident or data breach occurs?

Vanguard maintains a 24/7/365 Managed Detection and Response (MDR) capability via our dedicated Security Operations Center (SOC). In the highly improbable event of a validated security incident or unauthorized access to customer data, Vanguard commits to a strict notification SLA:

  • Impacted enterprise clients will be formally notified via their designated security contacts within 24 hours of incident validation.
  • Vanguard provides a comprehensive preliminary incident report detailing the scope of impacted data, initial containment actions executed, and continuous technical updates every 4 hours until full remediation is achieved.
